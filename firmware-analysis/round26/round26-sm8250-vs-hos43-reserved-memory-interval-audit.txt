Method: a local-only parser extracted each reserved-memory child's reg tuples
(#address-cells=2, #size-cells=2) into process memory, classified every ACK
child against every HOS fixed-reg child by exact base/size, same-base/different-
size, overlap, or no match, then emitted ONLY class names and coarse size
classes. Dynamic size/alloc-ranges pools were parsed separately and NEVER
treated as equal to a fixed reg tuple. No raw coordinate left the local host.

Size classes used: KiB-class / low-MiB / tens-of-MiB / hundreds-of-MiB / zero.

Redaction: every node unit-address suffix is written @[redacted]. No numeric
base, size, end or byte count appears below. This statement is the explicit
satisfaction of the task's "all coordinates compared locally and redacted from
upload" requirement.

Notes on classification integrity:

  - cdsp_secure_heap: ACK has a fixed reg; the HOS same-name child is a
    `no-map` node with NO fixed reg tuple. It is therefore NOT claimed equal

  - No ACK child was classified SAME_BASE_DIFFERENT_SIZE or OVERLAP against a
    HOS fixed node; those classes had zero members in this comparison.

HOS dynamic / no-fixed-reg nodes (13; cannot equal a fixed ACK interval):
  cdsp_secure_heap, adsp_region, sdsp_region, cdsp_region, mem_dump_region,
  sp_region, user_contig_region, qseecom_region, qseecom_ta_region,
  secure_display_region, cnss_wlan_region, linux,cma, mailbox_region.
  Of these, linux,cma and the *_region reusable pools are CMA-style shared
  pools (HOS side only); ACK sm8250.dtsi declares none.

Internal HOS duplicate/nested case (local observation, no coordinates):
  cont_splash_region and disp_rdump_region share the SAME base with DIFFERENT
  sizes (SAME_BASE_DIFFERENT_SIZE between two HOS fixed nodes). This is an
  HOS-internal nesting/overlap pattern; it is not an ACK-vs-HOS mismatch and is
  reported as an observation only, with no address published.

Parser limitations stated honestly:
  - Only immediate children of each /reserved-memory block were compared;
    nested subnodes (if any) were not separately classified.
  - A fixed tuple is compared by base and size; `no-map`/`reusable` flags are
    recorded but are not part of interval equality.
  - Unit-address text was stripped for reporting; equality was computed from
    parsed cell values in local memory, not from node names.

3. WORK PACKAGE C — what rev2 actually inherits
----------------------------------------------------------------------
Status: PARTIAL (inheritance is certain; safety of one node is unresolved).

rev2 candidate includes sm8250.dtsi at line 45 and does NOT declare its own
/memory or /reserved-memory (comment lines 334-349). Therefore, if built from
this source, the board DTB inherits:
  - all 18 ACK no-map fixed carveouts listed in section 1;
  - the top-level memory@[redacted] node (section 6);
  - the 6 SoC-level consumers (smem/gpu/slpi/cdsp/video/adsp) that reference
    those reservations via memory-region.
It does NOT inherit any HOS4.3 dynamic CMA/shared-dma-pool node, because those
exist only in the HOS base FDT, not in sm8250.dtsi.

Distinguish presence from probe: a reserved node being present in the DTB does
not mean its consumer driver probes. The minimal rev2 board file leaves most
top-level devices disabled, so e.g. gpu/video/adsp consumers may not bind at
first boot; reservation presence is nonetheless real and consumes address
space in the compiled DTB.

Overlap against ordinary HOS4.3 RAM: the usable RAM range is supplied by ABL at
boot and is NOT present as a fixed value in the HOS base FDT (both /memory
placeholders have zero size, section 6). Therefore whether any inherited ACK
fixed interval overlaps a real HOS RAM region is UNKNOWN until the final
post-ABL FDT is known.

4. WORK PACKAGE D — safe recommendation (design-only, no edits made)
----------------------------------------------------------------------
Status: PARTIAL / BLOCKED on final ABL FDT.

Per-node safety classification of the 18 inherited ACK nodes:
  - exact same interval as HOS4.3 (17 nodes) : hyp, xbl_aop, cmd_db, smem,
    removed, camera, wlan, ipa_fw, ipa_gsi, gpu, npu, video, cvp, cdsp, slpi,
    adsp, spss — safe on interval evidence (name differs, interval identical).
  - unmatched / potentially unsafe (1 node) : cdsp_secure_heap — ACK fixed
    interval vs HOS dynamic no-reg same-name node; cannot be shown equal.
    Whether the ACK fixed range collides with an HOS dynamic allocation or
    ABL/secure firmware memory is UNKNOWN; resolve only with the post-ABL FDT.
  - no fixed interval because dynamic pool : none on the ACK side (all 18 are
    fixed); HOS-only dynamic pools are listed in section 2.
  - unresolved without final ABL FDT : all overlap-with-RAM questions, and the
    cdsp_secure_heap fixed-vs-dynamic case.

Answers to the four required questions:
  1. Is inheriting pinned sm8250.dtsi reserved-memory safer than omitting all
     37 HOS4.3 reservations? On interval evidence, inheriting is the MORE
     defensible baseline: 17 of 18 ACK fixed reservations exactly match HOS
     fixed reservations, so it preserves real carveouts that omission would
     drop. It is safer on that narrow criterion, NOT proven safe overall.
  2. Does it risk reserving wrong ranges or overlapping ABL/secure memory?
     One node (cdsp_secure_heap) is a fixed-vs-dynamic mismatch and could be
     wrong; any overlap with ABL/secure memory or real RAM is UNKNOWN because
     no final post-ABL FDT is available. Risk is not zero and is not quantified.
  3. Can a minimal UFS-only candidate safely keep those generic nodes? The 17
     exact-match nodes can be kept on interval evidence. cdsp_secure_heap must
     NOT be asserted safe; keep it only as an inherited upstream node and treat
     it as an open item, not as an HOS-matching reservation. No node was
     deleted, replaced, or overridden in this round.
  4. What must remain blocked until the final post-ABL FDT is known? Any claim
     about usable RAM overlap, about cdsp_secure_heap equivalence, about
     ABL/secure-firmware reservation handoff, and any decision to add/remove/
     resize a reservation. The final memory gate stays BLOCKED.

No design change is authorized by this report; any future override must name
the exact node and its evidence, with no invented addresses.
