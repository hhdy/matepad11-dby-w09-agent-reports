### 5.2 ROUND139 — correction to consumer scope

ROUND139 stated that the pinned ACK tree has no consumer for either qcom,vddp-ref-clk-supply or qcom,vccq-parent-supply. This is accurate for unpatched stock ACK only.

The 23-patch candidate consumes qcom,vddp-ref-clk-supply in drivers/ufs/host/ufs-qcom.c (patch 06, ufs_qcom_init_vddp_ref_clk()); it does not consume qcom,vccq-parent-supply. The latter remains inert metadata in the candidate unless some other explicit consumer is added.

Carry forward the distinction:
- qcom,vddp-ref-clk-supply: consumed by the candidate patch series;
- qcom,vccq-parent-supply: no candidate consumer found;
- neither property establishes a PMIC physical input parent.

### 5.3 vdd-hba-supply omission

The candidate deliberately omits HOS4.3 vdd-hba-supply → ufs_phy_gdsc and represents the GDSC using the standard power-domains property instead. Pinned ufshcd_populate_vreg() treats a missing vdd-hba-supply as “assuming enabled” and returns success, so the omission does not fail regulator parsing.

This is statically coherent but remains a deliberate divergence from the vendor UFS supply declaration. It does not prove that the domain is enabled at the needed time or that HOS4.3's exact sequence is reproduced. Keep it visible for the independent architecture review.

### 5.4 MMCX domain

The candidate adds RPMHPD_MMCX as an additional UFS host power-domain. Pinned ACK's SM8250 mmcx descriptor has no .parent; the CX descriptor has an MX parent, but SM8250 maps MMCX to the plain descriptor. Therefore a candidate MMCX vote does not establish an MMCX→MX parent vote through that descriptor.

The static DTB property is correctly validated; actual RPMh vote propagation and physical corner equivalence remain UNKNOWN. Do not claim the added MMCX domain closes the runtime UFS performance gate.
