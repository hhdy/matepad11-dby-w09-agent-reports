4. STATIC SOURCE-FLOW FACTS (inputs to the required checks)
--------------------------------------------------------------------------------
All facts were read from the patched disposable worktree (apply state above),
plus pristine-vs-patched greps where noted.

  * The patch touches exactly two files. include/ufs/ufshcd.h is NOT in the
    diff (verified: git diff --name-only | grep -c include/ufs/ufshcd.h = 0).
  * New fields land in `struct ufs_hba_priv` (ufshcd-priv.h lines 13–15):
      struct async_domain async_domain;
      async_cookie_t      async_scan_cookie;
      bool                async_scan_scheduled;
    `to_hba_priv()` is `container_of(hba, struct ufs_hba_priv, hba)` — the
    public `struct ufs_hba` layout is untouched.
  * The pristine source had exactly one schedule site:
      async_schedule(ufshcd_async_scan, hba);            (ufshcd.c:11190)
    and ZERO async_synchronize call sites (grep over pristine ufshcd.c: none).
    The patched source has exactly one schedule site, now via the domain API,
    storing the cookie:
      priv->async_scan_cookie =
          async_schedule_domain(ufshcd_async_scan, hba, &priv->async_domain);
      priv->async_scan_scheduled = true;                 (ufshcd.c:11207–11210)
  * Domain initialization sits in `ufshcd_alloc_host()` (ufshcd.c:10861–10863):
      INIT_LIST_HEAD(&priv->async_domain.pending);
      priv->async_domain.registered = 1;
      priv->async_scan_scheduled = false;
    All three in-tree drivers call ufshcd_alloc_host() before ufshcd_init()
    (ufshcd-pltfrm.c:660, ufshcd-pci.c:648, tc-dwc-g210-pci.c:89), and the
    schedule point is at the very end of ufshcd_init() — so the domain is
    always initialized before any possible scheduling. kernel/async.c line
    171 confirms the schedule path consults domain->registered, i.e. setting
    it to 1 here is required and sufficient.
  * `ufshcd_remove()` (ufshcd.c:10716) begins with the join block:
      struct ufs_hba_priv *priv = to_hba_priv(hba);
      if (priv->async_scan_scheduled) {
          async_synchronize_cookie_domain(priv->async_scan_cookie + 1,
                                          &priv->async_domain);
          priv->async_scan_scheduled = false;
      }
    The to_hba_priv line is container_of pointer arithmetic (no HBA field
    read); the join is therefore the first teardown-relevant action and runs
    BEFORE the first HBA field read (hba->ufs_device_wlun at 10727) and
    before ufs_hwmon_remove/ufs_bsg_remove/... teardown.
  * host_sem survey:
      - ufshcd_remove() itself: no host_sem acquisition before the join.
      - callers: ufshcd_pltfrm_remove() body is pm_runtime_get_sync →
        ufshcd_remove → pm_runtime_disable (no host_sem); the two PCI
        drivers' remove paths call pm_runtime_forbid + pm_runtime_get_noresume
        then ufshcd_remove (no host_sem).
      - supporting fact: ufshcd_async_scan() itself does
        down(&hba->host_sem) ... up(&hba->host_sem) around ufshcd_probe_hba.
        Since no remove path holds host_sem when it joins, and the scan does
        not wait on anything remove holds, there is no lock-order cycle.
  * Sync-fallback semantics (kernel/async.c, async_schedule_node_domain):
      "If we're out of memory or if there's too much work pending already,
       we execute synchronously."  → func(data, newcookie); return newcookie;
    i.e. the callback has COMPLETED by the time the schedule call returns.
    Harmlessness of the stored checkpoint in that case: the synchronous
    branch never enqueues into domain->pending, so lowest_in_progress()
    returns ASYNC_COOKIE_MAX (kernel/async.c: empty pending list ⇒
    ASYNC_COOKIE_MAX), and the remove-side join
    wait_event(async_done, lowest_in_progress(domain) >= cookie+1)
    is trivially true → returns immediately.
  * In ufshcd_init(), after the schedule point only non-failing statements
    remain (trace_android_vh_ufs_update_sysfs, device_enable_async_suspend,
    ufshcd_pm_qos_init, return 0) — there is no failure path after
    scheduling; every earlier failure exits through out_disable/out_error
    without touching async_scan_scheduled.
