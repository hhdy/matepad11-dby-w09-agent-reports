0. 结论摘要（先给答案，证据见后续各节）
================================================================================

问题：HOS4.3 的 PM8150 L5 provider / regulator 节点是否声明了会影响 ACK
regulator_disable() 错误边界的 qcom,always-wait-for-ack 或 regulator coupling；
是否存在其普通 upstream regulator parent supply 属性；九个 stock DTBO 是否覆盖？

答案（全部为静态 FDT 证据，未含任何运行时推断）：

 (1) qcom,always-wait-for-ack：**三个 base 候选全树为零实例**；九个 DTBO 全树同样零实例。
     因此 ACK 的 disable 路径在本固件 DT 中完全不受该 vendor 标志影响。
 (2) Regulator coupling：**三个 base 候选全树不存在任何 coupling 属性**
     （regulator-coupled-with / -max-spread / -min-spread / -no-balance / qcom,coupling-spread
     全部为 0 实例）；因此不存在"RSC 子树内其他 regulator 反向耦合到 L5"的情形。
     L5 child 自身也未声明 coupling，三个 child（l5 / l5-ao / l5-so）均无。
 (3) Parent supply：L5 group 与三个 child 节点上**没有任何 *-supply / *-parent-supply**
     （vdd-l3-l4-l5-l18-supply、vin-supply、vdd-supply、vph-pwr-supply 均为 ABSENT）。
     唯一出现在 group 上的 supply 类属性是 vendor 的 proxy-supply，它不是物理输入。
 (4) Vendor proxy：`proxy-supply` 位于 L5 **group** 节点，phandle 解析后的唯一目标就是
     L5 child 自身 `/soc/rsc@18200000/rpmh-regulator-ldoa5/regulator-pm8150-l5`
     （即声明 qcom,proxy-consumer-* 的那个节点）。它**不证明**任何物理上游 input rail。
 (5) Overlay matrix：九个 entry **没有任何 fragment 指向 L5 group / 任一 L5 child /
     /soc/rsc@18200000 子树**，也没有任何 overlay 节点落在该子树下。
     因此 nine-entry 对上述 A/B/C 字段的修改数均为 0，合成后的 L5 属性值与 base 完全相同。
     九个 entry 在这一点上表现一致，"entry 8 才是实际生效 overlay"的假设不影响本结论。

 补充（非任务书要求项，单独标注）：九个 entry 均通过 fragment@63 把
 `/soc/ufsphy_mem@1d87000`（QMP UFS PHY，base 内 status="disabled" 且无 compatible）
 的 `vdda-phy-supply` 指向 pm8150_l5、`vdda-pll-supply` 指向 pm8150_l9，
 并同时加入布尔属性 `vdda-phy-always-on`、status="ok"。
 即 L5 在本固件中唯一的 overlay 引入消费者就是该 UFS PHY；L5 自身配置未被任何 overlay 触碰。

  朴素做法，会产生大量假引用：

    clocks（如 <&gcc N> 的第二个 cell 是 clock ID）、
    thermal-sensors（sensor ID）、
    reg、cell-id、cell-index、hw-tbuf、qcom,bc-elem-size、
    qcom,fuse-disable-bit、qcom,spcom-sp2soc-rmb-initdone-bit、qcom,spss-scsr-bits、
    qcom,sw-ctrl-gpio

  candidate_2 上该误命中合计 19 处 / 11 种属性名；朴素搜索会得到 28 条"引用"，
  其中只有 9 条是真正的 phandle 引用（全部为 *-supply 类）。
  证据：i2c@888000 的 clocks = <23 X 23 136 23 137> 呈 phandle+ID 交替模式：
  首 cell 是 clock provider 的 phandle，第二 cell 是该 provider 的 clock ID。
  X 的数值恰好等于 L5 的 phandle（本报告不记录该数值），但它在 clocks 语境中是
  clock ID，不是引用；同理 24/124 一类小整数在本树里大量作为 ID/偏移/位号出现。

  因此本报告的引用搜索**限制在 *-supply 语义类属性**（1 cell = 1 phandle），
  其余数值巧合单独计数并在此披露，未静默丢弃，也未计为引用。

  (a) DT 事实：L5 group 与三个 child 节点上**没有**任何普通 parent supply 属性。

  (b) 内核 regulator core 的 dummy fallback：若某个 consumer 用非 optional 的
      regulator 获取接口去取一个未在 DT 中声明的父电源，regulator core 可能返回
      dummy regulator（取决于内核配置与获取 API 选择）。这属于**内核代码语义**，

  不能当作物理输入 rail，因此不能用来填补 7.1 的空缺。
