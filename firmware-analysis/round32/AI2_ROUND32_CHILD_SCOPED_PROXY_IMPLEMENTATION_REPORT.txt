0. EXECUTIVE SUMMARY
--------------------------------------------------------------------------------
ROUND31 confirmed a topology blocker: the ACK board tree flattens the whole
PM8150 into ONE synthetic platform device ("pm8150-regulators"), whose of_node
is the regulator provider container. The ROUND31 group-level proxy-supply is
resolved with regulator_get(dev, "proxy") against that single provider device,
so only ONE proxy target can be expressed — L5 and L9 cannot each vote for
their own regulator, which is what the HOS4.3 evidence (ROUND13) shows the
original firmware does.

ROUND32 implements and verifies the child-scoped mechanism:

  * each regulator child node may carry its own `proxy-supply` phandle; the
    proxy consumer handle is then resolved BY THAT CHILD'S NODE via the pinned
    core's existing exported API of_regulator_get(dev, node, id);
  * legacy provider-level group behavior is byte-for-byte unchanged when no
    child carries proxy-supply;
  * child-scoped + provider-level declaration on the same provider is
    rejected at registration with -EINVAL (explicit, testable — no silent
    priority);
  * -EPROBE_DEFER (target rdev not yet registered / coupling unresolved —
    the normal case for self-targets) parks the consumer; a late_initcall
    (level 7) retry re-resolves parked consumers once, strictly BEFORE the
    late_initcall_sync (7s) bulk revoke;
  * the three-patch series (driver, binding, review DTS) is committed on the
    stagea branch together with the previously-missing reproducible test
    harness (fixing the recorded ROUND31 defect that the 38-check harness
    was never committed).

Verification: 15/15 patches apply (45/45 rc=0), checkpatch 0 errors,

2. DESIGN GATE — THE PINNED CORE ALREADY HAS A SAFE REGULATOR-BY-NODE API
--------------------------------------------------------------------------------
All line numbers refer to the pinned commit 8ad08f75ddf056e1ee600e1339e0463c5f
cbdc9a. Conclusion of the gate: NO new core API is required; the mechanism is
built entirely on existing exported core surfaces, so no device is faked and
no reference count is bypassed.

Evidence chain:

(1) of_regulator_get(dev, node, id) EXISTS and is EXPORT_SYMBOL_GPL
    (drivers/regulator/of_regulator.c), declared __must_check in
    include/linux/regulator/consumer.h.
      of_regulator_get -> _of_regulator_get ->
        _regulator_get_common_check()
        of_regulator_dev_lookup(dev, node, id)
        _regulator_get_common(rdev, dev, id, type)   [core.c:2204]
    _regulator_get_common is the SHARED allocation path used by every
    consumer_get: coupling check, regulator_resolve_supply(), module refcount,
    create_regulator() under regulator_lock(), open_count accounting,
    device_link_add(). Nothing is invented around it.

(2) Lookup semantics:
    of_get_regulator(dev, node, supply) reads `<id>-supply` from the EXPLICIT
    node via of_parse_phandle(); its fallback of_get_child_regulator() is a
    RECURSIVE descent — which is precisely why the ROUND31 group-level shape
    could not distinguish L5 from L9.
    of_regulator_dev_lookup (of_regulator.c:663) resolves the phandle, finds
    the rdev by node via of_find_regulator_by_node ->
    class_find_device_by_of_node (class-core refcount +1, released by the
    matching regulator_put), and returns -EPROBE_DEFER when the node exists
    but no rdev is registered yet.

(3) Defer vs dummy: _regulator_get_common's dummy-regulator fallback triggers
    ONLY on -ENODEV; -EPROBE_DEFER propagates untouched. "Target not
    registered yet" is therefore distinguishable from "no such supply" —
    the exact property the deferred-parking design needs.

(4) Plain regulator_get() is safe by the same route: regulator_get
    (core.c:2358) -> _regulator_get (:2331) -> regulator_dev_lookup (:2003)
    -> regulator_dt_lookup (:1975) -> of_regulator_dev_lookup(dev,
    dev_of_node(dev), supply) — the legacy path only ever reads the consumer
    device's OWN node, which is why legacy behavior is unaffected by this
    round.

(5) Coupling: non-coupled regulators are initialized with n_coupled =
    n_resolved = 1 (regulator_init_coupling), so self-targets pass the
    coupling gate in _regulator_get_common immediately.

The gate therefore PASSES: the by-node path uses the standard class-device
lookup with its refcount, and the handle lifecycle is the standard
regulator_put path (_regulator_put -> put_device). No fabrication required.

3.1 Driver semantics (patch 13)
  * struct proxy_consumer gains reg_dev / reg_node / child_scoped / deferred.
  * Resolution: child node has `proxy-supply` ->
      of_regulator_get(reg_dev, reg_node, "proxy")   (child-scoped)
    child node has none ->
      regulator_get(reg_dev, "proxy")                (legacy ROUND31 path,
      unchanged, including its recursive child search on the provider node).
  * AMBIGUITY GATE: child-scoped declaration while the provider node ALSO
    carries `proxy-supply` -> dev_err + -EINVAL, no lookup performed.
    Chosen over a silent priority rule because it is explicit and testable
    (taskbook §3 requires "clear precedence or reject ambiguity").
  * Shared vote helper proxy_consumer_apply_votes() applies load/enable with
    REVERSE-ORDER rollback on partial failure (registered in System.map as a
    static symbol; see §8 evidence).
  * Error paths: set_load failure -> no enable; enable failure -> load vote
    withdrawn; any failure -> regulator_put once, rdev back-pointer cleared.
    All covered by tests (§7).

3.2 Deferred parking and retry (patch 13)
  * rc == -EPROBE_DEFER at registration -> the consumer is PARKED, not an
    error: reg handle stays NULL, no vote is made, the consumer is queued,
    registration returns the consumer so the rdev back-pointer and a later
    unregister still clean it up.
  * regulator_proxy_consumer_remove() on a parked consumer (reg == NULL)
    releases it without touching any regulator.
  * A late_initcall (level 7) retry pass, regulator_proxy_consumer_retry_
    deferred, re-resolves parked consumers ONCE and applies their votes; a
    vote failure inside the retry unwinds and frees the consumer (back-
    pointer cleared, logged). During implementation a use-after-free was
    found and fixed in this path (the failure log referenced consumer->
    reg_node after kfree; the pr_err now runs before the release).
  * Consumers still parked at the bulk revoke are dropped WITHOUT EVER HAVING
    VOTED (explicit log). Nothing claims a rail was kept on.
  * Ordering proof: the retry is linked at level 7, the bulk revoke at 7s;
    kernel late_initcall (7) strictly precedes late_initcall_sync (7s).
    This is verified at LINK LEVEL from the built System.map — see §8.

3.3 Kconfig (patch 13, follow-up hunk — allowed)
  REGULATOR_PROXY_CONSUMER now `depends on OF`. Reason: the child-scoped
  path calls of_regulator_get(), which has NO !CONFIG_OF inline stub in the
  pinned consumer.h (only the _optional variants have one) — building without
  OF would fail at link time. Proxy properties only ever come from DT, so the
  dependency is semantic, not just mechanical.

3.4 Binding (patch 14) — see §5 for the negative-control consequences.

3.5 Review DTS (patch 15)
  dby-w09-proxy-review.dts expresses the HOS4.3 ROUND13 evidence in the ACK
  flattened shape (provider "pm8150-regulators", qcom,pm8150-rpmh-regulators):

4. LIFECYCLE / SELF-TARGET TIMING PROOF (taskbook §4)
--------------------------------------------------------------------------------
* Per-child handles: each child-scoped consumer owns an independent struct
  regulator handle; unregister of one child never touches the other (tested:
  l5 unregister -> l9 not disabled, l9 handle untouched).
* Bulk revoke: late_initcall_sync hook runs once; per-rdev back-pointers are
  cleared inside regulator_proxy_consumer_remove(), so individual unregister
  and bulk revoke can never act on the same consumer twice; repeated teardown
  is a no-op (tested).
* Self-target timing (source-level proof at the pinned commit):
    regulator_register() sets rdev->dev.of_node = of_node_get(config->of_node)
    (core.c:5880) and calls device_add(&rdev->dev) BEFORE rdev_init_debugfs()
    (:5998). The proxy hook runs after both, so at hook time
    class_find_device_by_of_node already finds the just-registered rdev: a
    child whose proxy-supply phandle points at ITSELF resolves to its own
    rdev. No recursion into regulator_register occurs and no lock is held
    across the lookup. (For self-targets the coupling is not yet resolved at
    hook time — this is exactly the case the deferred parking covers.)
* Target unregister window: core regulator_unregister() carries
  WARN_ON(rdev->open_count) — a regulator with a live consumer handle cannot
  be unregistered; for self-targets the handle is dropped inside the same
  driver, so no such window exists.
* Cleanup semantics inherited from ROUND31: revoking proxy votes neither
  guarantees a rail turns off nor that it stays on — the core's delayed
  unused-regulator cleanup runs after the revoke decision point. No
  always-on semantics were introduced.

5. BINDING — STRICT, WITH DOCUMENTED META-SCHEMA LIMITATION (taskbook §3)
--------------------------------------------------------------------------------
* Child-level `proxy-supply` declared inside the existing
  ^(smps|ldo|lvs|bob)[0-9]+$ patternProperties; additionalProperties /
  unevaluatedProperties flags preserved everywhere; NO key relaxed.
* Provider-level proxy-supply description extended (legacy mapping + the
  mixing prohibition, enforced at runtime by the -EINVAL gate).
* `$ref: dtschema/definitions/phandle` was deliberately NOT added: the
  dtschema META-SCHEMA (core.yaml, rule on '-supply$') restricts every
  *-supply property to keys {description, deprecated} only. Adding a $ref
  FAILS dt-doc-validate (observed RC=1, then removed — this is the honest
  negative-control outcome, not a shortcut).
* Consequences, all covered by fixtures and asserted in the gate (§6.3):
    - a plain u32 instead of a phandle cannot be rejected at schema level;
      accepted by the validator, surfaces at RUNTIME as -EPROBE_DEFER (the
      "phandle target" never registers). Documented, not hidden.
    - a dangling LABEL reference is rejected by dtc at COMPILE time
      (negative fixture round32-proxy-child-scoped-bad-phandle.dts:
      phandle_references ERROR, RC=2).
